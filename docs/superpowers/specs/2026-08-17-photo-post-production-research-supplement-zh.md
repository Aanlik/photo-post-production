# 照片后期处理 Skill 外部方案吸收与闭环升级补充规格

**日期：** 2026-08-17
**状态：** 补充开发规格，待分阶段实现
**适用对象：** `photo-post-production` Skill 的分类、评分、个性化学习、后期规划、Lightroom/Photoshop 执行和质量验收模块
**依赖主规格：** [照片后期处理 Skill 设计规格](./2026-08-14-photo-post-production-skill-design-zh.md)

## 1. 文档目的

本文档把 GitHub 和公开资料中已经出现的自动选片、RAW 后期、个人风格学习和闭环代理方案，转换为当前 Skill 可实施的增量设计。本文档不替代主规格，只补充以下缺口：

- 多模型、分类别、可解释的照片评分；
- 从用户保留、淘汰、A/B 选择和修改意见中学习个人偏好；
- 从“一次性生成参数”升级为“观察、规划、执行、评价、回退”的后期闭环；
- 根据照片和操作类型选择 Lightroom、Photoshop、确定性本地工具或生成式工具；
- 整组照片的视觉一致性和系列叙事；
- Photoshop UXP、DCC MCP、`batchPlay` 和 Action Descriptor 的职责分工；
- 用明确测试证明照片真的发生了有效且审美上合理的改变。

## 3. 核心设计结论

### 3.1 Skill 负责决策，不直接假装拥有编辑能力

Skill 是导演和编排层，负责判断照片价值、后期目标、操作顺序、风险和停止条件。像素修改必须由经过能力检查的执行器完成。任何计划、提示词或操作清单都不能被报告为已完成后期。

### 3.2 不把一个通用审美分当作真理

每张照片同时保存：

- 确定性技术指标；
- 模型审美指标；
- 类别专属指标；
- 用户偏好匹配度；
- 后期可改善程度；
- 评分置信度和证据来源；
- 技术硬门槛。

最终是否处理仍由 `keep_value`、`editability` 和 `candidate_potential` 决定，但三项分数必须能追溯到各维度证据，不能只保留最终数值。

### 3.3 后期必须是闭环，不是一次性参数生成

每轮后期遵循：

```text
观察当前图像
→ 识别最大视觉问题
→ 选择少量原子操作
→ 执行并渲染
→ 比较原片、上一最佳版本和当前版本
→ 接受、回退或生成下一轮操作
```

默认最多三轮。第一版采用有界 beam search 或候选排序，不直接实现高成本 MCTS。只有当固定测试集证明候选搜索能显著降低用户修改率时，才考虑加入 MCTS。

### 3.4 一张照片只保留一个 Photoshop 主文档

Lightroom 负责 RAW 解码和全局基础；Photoshop 在一个 PSD 内通过图层、组、蒙版、智能对象和历史快照完成精修。逻辑操作节点只写清单和历史信息，不生成多个 TIFF、PSD 或阶段性 JPG。

最终常规交付只允许：

- 一个分层 PSD；
- 一个高质量全尺寸 JPG；
- 可选一个分享尺寸 JPG；
- JSON 报告、操作清单和审核图。

Lightroom 到 Photoshop 的 16-bit TIFF 是临时交接文件，成功写入 PSD 并校验后删除。

## 4. 目标架构

```text
输入与资产组
  ↓
预览和确定性分析
  ↓
多模型分类与评分
  ↓
连拍/近重复选择
  ↓
用户偏好与项目风格融合
  ↓
导演简报和系列锚点
  ↓
后期规划器
  ├─ Lightroom 全局执行器
  ├─ Photoshop UXP/DCC 执行器
  ├─ 本地确定性工具执行器
  └─ 生成式编辑执行器
  ↓
渲染和视觉评价器
  ↓
接受 / 回退 / 下一轮
  ↓
导出验证和反馈学习
```

所有执行器必须返回统一结果：`operation_id`、实际输入、实际输出、前后哈希、实际参数、应用程序和版本、文档 ID、图层 ID、耗时、警告和可回退检查点。

## 5. 分类与评分升级

### 5.1 分析层级

评分采用四层证据：

1. **确定性技术层：** 尺寸、直方图、溢出、模糊、噪点、动态范围代理、色偏、EXIF、RAW 可读性。
2. **视觉模型层：** 主体、人物、动物、天空、建筑、文字、显著性、构图、场景类型和相似度。
3. **摄影评价层：** 瞬间、情绪、叙事、视觉层次、主体关系、画面完整性和原创性。
4. **个人偏好层：** 用户在相同类别中的历史保留、淘汰、版本选择和局部修改。

### 5.2 类别模型

必须至少支持：

- `landscape-nature`
- `urban-landscape`
- `architecture-urban-space`
- `street-documentary`
- `portrait-environmental`
- `animal-wildlife`
- `plant-macro`
- `other-unsupported`

新增 `plant-macro`，避免植物、花卉、昆虫和细节照片长期落入其他类。可同时保留 `macro`、`low-light`、`crowd`、`backlit`、`motion`、`minimal` 等副标签。

### 5.3 类别权重

不同类别使用独立权重，但共享字段定义。例如：

- 人像提高眼神、表情、肤色、姿态和背景干扰权重；
- 街头/纪实提高瞬间、人物关系、叙事和场景真实性权重；
- 风光提高光线、空间层次、天气、前中后景和高光恢复权重；
- 动物提高眼睛清晰度、姿态、行为瞬间、毛发/羽毛和背景分离权重；
- 植物/微距提高焦平面、细节、形态、色彩关系和背景洁净度权重。

分类置信度不足时，评分输出多个类别假设，并采用保守的加权合并；不得强行选择高分标签。

### 5.4 评分记录扩展

在现有 score record 基础上增加：

```json
{
  "model_signals": {},
  "deterministic_signals": {},
  "category_weights_version": "",
  "preference_model_version": "",
  "preference_fit": 0,
  "burst_rank": null,
  "comparative_reasons": [],
  "edit_outlook": {
    "largest_problem": "",
    "likely_result": "",
    "recommended_operations": [],
    "unrecoverable_limits": []
  }
}
```

`comparative_reasons` 必须解释同一连拍组中为什么 A 优于 B，而不只是分别给分。

## 6. 个人审美学习

### 6.1 反馈来源

只有显式反馈可以训练偏好：

- 保留/淘汰；
- A/B 版本选择；
- 星级或分数；
- “太暗”“裁切太紧”“肤色不自然”等文字反馈；
- 用户在 Lightroom 或 Photoshop 中对 AI 结果做出的参数修正；
- 最终是否分享、导出或删除成片。

自动评分、模型自评和未确认的暂停状态不能作为用户偏好。

### 6.2 学习方式

第一阶段采用分类别 Bradley-Terry 或逻辑回归偏好模型，输入为两张照片或两个候选版本的特征差值。模型分别学习：

- 选片偏好；
- 裁切偏好；
- 亮度和对比度偏好；
- 色温与色彩偏好；
- 人像美化强度；
- 生成式改动接受度。

模型更新必须满足：

- 达到最小有效样本数；
- 交叉验证不低于旧版本；
- 不突破技术硬门槛；
- 保留旧版本并可回退；
- 项目偏好和长期偏好分开训练。

### 6.3 冷启动

新用户或新类别没有足够反馈时，使用通用类别权重和当前项目校准。不得因缺少历史偏好降低照片技术质量要求，也不得声称已经形成个人风格。

## 7. 后期规划器

### 7.1 原子操作

规划器只生成可验证的原子操作，例如：

- `crop-and-straighten`
- `global-tone`
- `white-balance`
- `color-separation`
- `subject-relight`
- `background-restraint`
- `local-dodge-burn`
- `skin-tone-correct`
- `skin-texture-retouch`
- `liquify-bounded`
- `remove-distraction`
- `perspective-correct`
- `selective-sharpen`
- `noise-reduce`
- `generative-fill`
- `generative-expand`

每个操作必须说明要解决的问题、成功判据、风险、区域、预期变化和所需执行器。不得使用“整体变高级”“更有电影感”作为不可验证操作。

### 7.2 执行器路由

| 操作类型 | 首选执行器 | 后备执行器 |
| --- | --- | --- |
| RAW 解码、镜头、白平衡、基础曝光、全局色彩 | Lightroom | RawTherapee/darktable 本地 CLI |
| 图层、蒙版、局部明暗、复杂色彩、修复、液化、变形 | Photoshop UXP/DCC | Photoshop UI 自动化并强校验 |
| 元数据、尺寸、格式、基础旋转 | ExifTool/ImageMagick/Pillow | macOS 系统工具 |
| 元素补绘、扩图、重大内容重构 | 当前聊天窗口生成式工具或已验证本机后端 | 跳过并明确降级 |

Photoshop 路由采用三级能力：

- `stable-auto`：经过真实测试的结构化 DCC 工具；
- `descriptor-verified`：经过注册、回放和视觉验证的 `batchPlay` Action Descriptor；
- `ui-assisted`：只有前两层无法实现时使用，并要求操作前后确认文档 ID、图层和可见像素变化。

### 7.3 Photoshop Action Descriptor 注册表

使用 Bolt UXP 建立本机 Bridge 工程，使用 Alchemist 或 Photoshop `Copy as JavaScript` 捕获动作。描述符注册时记录：

- Photoshop 版本和平台；
- 动作名称、类型和 JSON；
- 支持的文档模式、位深和色彩空间；
- 参数化字段及范围；
- 是否包含 Raw Data；
- 是否依赖当前选区、图层或工具状态；
- 测试图片和预期视觉变化；
- 可逆性与回退方式；
- 最后通过测试的时间。

液化、修复笔触、仿制图章、复杂变形和生成式 Photoshop 命令不得使用未经注册的描述符。

## 8. 闭环评价器

### 8.1 三类评价

每次渲染后分别计算：

- **技术评价：** 清晰度、噪点、溢出、色带、光晕、边缘、纹理、色彩配置和尺寸；
- **语义评价：** 人脸、肢体、建筑、文字、反射、重复结构、背景人物和新增/删除内容；
- **摄影评价：** 主体层级、构图完整性、明暗动线、色彩关系、情绪、叙事和风格目标匹配度。

摄影评价必须提供结构化理由，不能只产生一个分数。

### 8.2 接受与回退

新候选只有同时满足以下条件才能替换当前最佳版本：

- 没有新增关键技术失败；
- 没有主体、人物或几何语义破坏；
- 目标问题出现可测量改善；
- 综合质量改善超过最小阈值；
- 没有明显违背用户偏好或导演简报。

如果只是整体更亮、更艳或更锐，但主体层次、构图和视觉关系没有改善，视为无效迭代。

### 8.3 局部评价

人像必须至少检查：

- 面部身份和五官比例；
- 皮肤纹理是否保留；
- 肤色是否自然；
- 眼睛、牙齿和头发边缘；
- 液化是否影响背景直线；
- 人物与环境的明暗关系。

街头/纪实必须检查是否破坏事件真实性；风光和建筑必须检查天空边缘、树线、建筑直线和反射；动物必须检查眼睛、毛发/羽毛和肢体结构；植物/微距必须检查焦平面、花瓣/叶片边缘和背景光斑。

## 9. 系列与批量一致性

借鉴 Adobe 批处理 Skill，批量任务先选定一张或多张风格锚点。锚点保存：

- 白平衡区间；
- 黑位和高光逻辑；
- 对比度曲线；
- 色彩关系；
- 颗粒与锐化语言；
- 裁切比例和视觉密度；
- 人像肤色范围。

每张照片可以偏离锚点以适配曝光和场景，但偏离必须记录原因。系列一致性分与单张质量分分开，避免为了统一而牺牲单张照片。

## 10. 审核体验

审核继续在聊天窗口完成，默认展示缩略图而不是要求用户按编号去文件夹寻找照片。

每张候选必须显示：

- 文件名和稳定审核编号；
- 主类别和副标签；
- 三项核心分数及维度解释；
- 连拍组内排名和胜出原因；
- 最大问题和不可恢复限制；
- 预计后期方向；
- 原片、当前最佳版本和必要的 100% 局部图；
- 是否会使用生成式或结构性修改。

用户可以用自然语言批量决定，例如“这一组除 8、11 外都保留”。系统必须把自然语言解析为稳定照片 ID，并回显实际命中的文件，防止编号漂移。

## 11. 新增模块和数据契约

建议新增或扩展以下模块：

| 模块 | 职责 |
| --- | --- |
| `model_signal_adapter.py` | 统一接收 CLIP、TOPIQ、Vision、面部、显著性等模型信号 |
| `category_weighting.py` | 管理分类别评分权重和版本 |
| `preference_model.py` | 训练、验证和回退分类别偏好模型 |
| `comparative_ranker.py` | 连拍组和候选版本的成对比较 |
| `edit_planner.py` | 根据最大问题生成原子操作和候选路线 |
| `executor_router.py` | 在 Lightroom、Photoshop、本地 CLI 和生成式后端之间路由 |
| `action_descriptor_registry.py` | 注册、验证和选择 Photoshop 动作描述符 |
| `render_evaluator.py` | 技术、语义和摄影三类渲染评价 |
| `series_cohesion.py` | 风格锚点、组图一致性和序列建议 |
| `learning_audit.py` | 记录偏好模型为何更新或拒绝更新 |

现有 `score-record.schema.json`、`edit-plan.schema.json`、运行清单和 SQLite 数据库需要增加模型版本、权重版本、偏好版本、执行器路由、前后评价及最佳候选引用。

## 12. 实施顺序

### P0：防止再次出现无效长运行

- 在执行 Photoshop 前计算预计磁盘峰值；
- 强制一张照片一个 PSD；
- 禁止为逻辑节点生成 TIFF/PSD；
- 每个关键操作后生成低成本预览并检查像素变化；
- 发现连续两个无效操作立即停止；
- UI 自动化前验证活动文档 ID 和主文件路径。

### P1：评分和审核升级

- 增加 `plant-macro`；
- 增加模型信号适配层；
- 实现类别权重版本；
- 增加连拍组比较理由；
- 在聊天审核图中展示后期展望和不可恢复限制。

### P2：个人偏好模型

- 把现有成对反馈转换为训练样本；
- 实现分类别 Bradley-Terry/逻辑回归；
- 增加最小样本和交叉验证门槛；
- 支持停用、重置和回退偏好版本；
- 报告个人偏好对最终排序的实际影响。

### P3：Photoshop UXP 高级动作库

- 用 Bolt UXP 建立独立本机插件工程；
- 连接现有 DCC broker；
- 暴露结构化 DOM 与原始 `batchPlay` 两条通道；
- 使用 Alchemist 捕获并验证高级动作；
- 首批覆盖曲线、色彩平衡、选择性颜色、内容识别修复、Dodge & Burn、频率分离、液化和透视变形；
- 每个动作建立真实照片回归样本。

### P4：闭环后期规划器

- 从固定顺序改为问题驱动的原子操作；
- 实现最多三轮的 beam 候选选择；
- 增加上一最佳版本回退；
- 引入局部区域和类别专属评价；
- 记录停止原因和被拒绝候选；
- 证明闭环能降低用户二次修改率后，再评估 MCTS。

## 13. 验证矩阵

至少准备以下真实 RAW 回归集：

- 5 组人像/环境人像；
- 5 组街头/纪实连拍；
- 5 组自然风光；
- 3 组城市/建筑；
- 3 组动物；
- 3 组植物/微距；
- 低光、逆光、严重高光、轻微失焦和不可恢复失败样本各若干。

每次版本升级必须记录：

- 分类准确率和低置信度比例；
- 连拍优选与用户选择一致率；
- 技术失败误接受次数；
- 高潜力照片漏选次数；
- 用户修改率；
- 用户候选选择率；
- 无效操作率；
- 回退成功率；
- 单张平均处理时间；
- 单张磁盘峰值；
- PSD/JPG 数量是否符合交付契约；
- 人物、建筑、文字和生成式语义破坏次数。

## 14. 验收门槛

补充能力完成的最低条件：

1. 原始 RAW 写入次数为 0。
2. 每张照片最多一个最终 PSD，临时 TIFF 在成功交接后删除。
3. 技术硬门槛失败却被自动接受的次数为 0。
4. 没有可见像素变化的操作不能被报告为成功精修。
5. Photoshop UI 操作命中错误文档的次数为 0。
6. 偏好模型没有足够样本或验证退化时不得更新。
7. 用户可以在聊天窗口完成批量保留、淘汰和版本选择。
8. 最终报告能解释照片为何入选、做了什么、为什么改善、还存在哪些限制。
9. `competition-standard` 只能表示通过本 Skill 内部质量门，不能保证真实比赛结果或规则合规。
10. 固定回归集中，闭环版本的用户二次修改率应低于一次性参数版本，否则不得宣称闭环升级有效。

## 15. 明确不采用的设计

- 不把 Adobe、Imagen、Bria 等云端 API 作为默认或必需后端；
- 不直接依赖尚未发布完整代码的 PhotoAgent；
- 不把 Facet 或任何审美模型的单一分数当作最终真理；
- 不让大模型直接生成未经验证的 Photoshop `batchPlay` 描述符；
- 不默认对每张照片运行全部 Lightroom 和 Photoshop 工具；
- 不因为用户授权充分就无条件执行大幅生成式修改；
- 不用多个 PSD/TIFF 代替 Photoshop 图层和历史记录；
- 不用“已运行”“已保存”代替视觉质量验收；
- 不以复杂提示词要求用户选择执行后端或技术模式。

## 16. 最终目标

升级后的 Skill 应形成一个本机优先、可解释、可学习、可回退的摄影后期代理：先理解照片是否值得处理，再理解它最需要解决的问题，选择恰当工具完成少量有效操作，逐轮验证是否真正变好，最后只交付具有明确摄影意图、技术完整性和可编辑来源的成片。
