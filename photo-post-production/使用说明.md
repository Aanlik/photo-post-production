# 照片后期 Skill 使用说明

## 最短用法

命令示例中的 `<PHOTO_SKILL_ROOT>` 指当前安装的 `photo-post-production` 目录；本机通常是 `/path/to/local-user/.codex/skills/photo-post-production`。

直接用自然语言描述即可，不需要写 Skill 名称、后端、提示词或处理步骤。例如：

> 处理“下载/本次拍摄”文件夹，自动分类、评分、筛选、精修并输出高质量 JPG 和可编辑 PSD。

Skill 会自动选择相关 Skill 和工具，默认采用自然增强、混合本地流程和自动模式：Lightroom 负责 RAW 与全局调整，Photoshop 负责精细后期，需要生成式修改时自动调用当前聊天窗口的 `image_gen`。Adobe 已启动时不需要用户手动填写适配器环境变量；流程会自动探测本机 Lightroom MCP 和 Photoshop Bridge。原始 RAW 永不改写，结果写入新的运行文件夹。用户不需要逐张确认或编写提示词。

## 分类

主分类固定为：风光/植物、城市风景、建筑/城市空间、街头/纪实、人物/环境肖像、动物/野生动物、其他/待确认。分类只是组织照片和选择后期策略，不会限制用户授权的后期范围。

## 评分

每张照片显示三项独立评分，并在真实渲染后追加“最终成片分”；最终分会回写到 `scores.json` 和 `scores.csv`：

- 保留价值：主体、瞬间、叙事和摄影价值。
- 可编辑性：曝光、色彩、细节、裁切和局部调整的安全空间。
- 预期收益：后期后预计能提升多少表达。
- 最终成片分：只根据真实输出、语义检查和导出检查计算；等待适配器时不会伪造。

候选分为：`保留价值 × 65% + 可编辑性 × 20% + 预期收益 × 15%`。评分旁边会记录得分原因、风险、置信度和“后期后可能变成什么样”。高分但低置信度的照片在自动模式进入保守跳过/等待队列，不执行未经验证的生成式变换。

## 聊天窗口审计（可选）

自动模式不会等待人工审核；A/B/C 联系表仅作为运行报告和聊天审计结果。需要人工接管时，可以直接说：

- `A 区都保留`
- `8、11 淘汰，其余保留`（在当前显示区内）
- `A01、A04 不要，其余的都要`
- `A02 保留，但降低曝光，保留更多天空`

未提供人工决定时，Skill 按固定策略继续执行；只有用户明确要求 review，或质量/能力检查失败时才暂停。

## 后期与输出

Photoshop 后期不是固定的几项基础调整。Skill 会先根据最终目标规划工具链，再按风险调用对应工具：

- 图层：创建组、复制图层、重命名、透明度、可见性、混合模式、图层蒙版。
- 橡皮擦：默认转成“隐藏选区”的非破坏性蒙版，不直接毁掉原像素。
- 去除元素：在复制的像素图层上执行内容识别填充，并要求检查边缘。
- 人像美化：人物皮肤局部平滑、脸部明暗和色调层；默认保留皮肤纹理，不自动磨皮或改变身份特征。
- 液化、修复画笔、仿制图章、减淡/加深、透视变形、锐化、模糊、降噪等：支持本地 Photoshop Action Descriptor；需要先在 Photoshop 中录制具体笔刷/几何动作，避免 AI 凭空猜测笔触。
- 构图：最后再进行大幅裁切，保留前后检查点。

同一张照片/同一变体只打开一个 Photoshop 文档：所有操作通过图层、蒙版和 History/History Snapshot 完成回退。中间操作只保存蒙版、工具参数、操作清单和哈希，不保存独立 PSD/JPEG；最终操作才保存一个分层 PSD，并输出 `web-share` 和 `competition-quality` 两个 JPG。Lightroom 到 Photoshop 之间使用新的 16-bit TIFF 检查点，避免直接把 RAW 交给 Photoshop；如果 Lightroom 目录中没有按路径找到照片，会用唯一文件名回查，重名时安全暂停。蒙版或工具执行无效时会停止导出，不会生成看似成功的错误 JPG。裁切支持像素坐标和 0–1 归一化坐标。当前桥接器的 `print-master` TIFF 保存能力未通过验证，桥接器通过健康检查后再启用打印主文件。

JPEG 输出默认质量 100，并独立检查尺寸、ICC、EXIF/XMP、软件信息、源文件哈希、结果哈希和 PSD 主文件证据。`competition-quality` 只是输出规格，不等于自动保证艺术质量；最终是否达到你的审美目标仍以真实前后对比和质量门结果决定。

## 聊天窗口生成式后端

本 Skill 默认采用 `mixed` 模式：

- Lightroom / Camera Raw：本地解码 RAW、曝光、白平衡、曲线、镜头和全局色彩。
- Photoshop：本地图层、蒙版、液化、修复、仿制、减淡/加深、人物精修和最终导出。
- 当前 ChatGPT/Codex 聊天窗口的内置 `image_gen`：当固定流程判断生成式修改能改善成片时自动处理，例如移除元素、局部重绘、扩图、换天空或增加元素。

生成式步骤不走 OpenAI API、不需要 `OPENAI_API_KEY`。原始 RAW 不会直接交给聊天窗口；必须先由 Lightroom 或 Camera Raw 输出本地 PNG/JPEG/WebP，再由宿主自动将目标预览显示到当前对话。聊天窗口按“一张图片/一个变体一次内置 image_gen 调用”执行，结果回写后再作为新图层导入 Photoshop，并保存提示词、输入/输出哈希和操作披露。

流水线保持聊天窗口 Hybrid 策略时：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/run_pipeline.py" \
  --input "/绝对路径/原始照片文件夹" \
  --output "/绝对路径/新的运行文件夹" \
  --mode auto \
  --intent competition-standard \
  --processing-locality mixed
```

`mixed` 运行会把生成式任务标记为 `awaiting-host-imagegen`，由当前聊天宿主逐张处理；如果当前会话没有暴露内置 `image_gen`，任务保持待处理或降级为 `global-only`，不会偷偷改走 API。若只想本地处理，使用 `--processing-locality local-only`。

需要查看或创建聊天窗口批处理清单时：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/chat_window_image_backend.py" --probe
```

自动筛选出符合门槛的照片后，运行会生成 `chat-window-results/chat-window-image-batch.json`。每一项包含源图哈希、内部提示词、不变约束、状态和输出路径，但不嵌入图像数据，也不保存 API Key。宿主自动逐张调用内置 `image_gen`，完成后用 `record_result(...)` 回写，Skill 再继续 Photoshop 图层合成和高质量 JPG/PSD 导出。

宿主自动逐张调用内置 `image_gen`，完成后用 `record_result(...)` 回写；随后通过运行清单继续 Photoshop 图层合成和高质量 JPG/PSD 导出。没有宿主工具时，任务会停在可恢复状态，不会把清单当成成片。

## 从命令行准备批量任务

需要先生成预览和技术清单时：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/prepare_batch.py" \
  --input "/绝对路径/原始照片文件夹" \
  --output "/绝对路径/新的运行文件夹"
```

输出目录会包含 `batch-manifest.json` 和 `previews/`，原始照片不会被改写。之后把清单和联系表交给当前聊天继续分类、评分、审核和后期。

## 一键生成审核板和可恢复队列

如果希望一次完成本机预览、视觉分类、评分、解释、A/B/C 联系表、候选后期计划和断点队列，可直接运行：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/run_pipeline.py" \
  --input "/绝对路径/原始照片文件夹" \
  --output "/绝对路径/新的运行文件夹" \
  --mode auto \
  --intent competition-standard
```

macOS 会优先使用本机 Apple Vision 提供人物、动物、建筑、街道、风光和文字等视觉证据；不可用时自动降级为保守跳过/等待，不伪造语义证据。运行目录会生成 `report.json`、`scores.json`、`scores.csv`、`review-A.jpg`、`review-B.jpg`、`review-board.md`、`execution-plan.json`、`execution-results.json`、`quality-report.json`、`rollback-ledger.json`、`rejected.json`、`variants/` 和 `queue.sqlite3`。高潜力照片的每个变体都有独立的 `edit-plan.json`、`edit-manifest.json` 和 `masks/` 目录；`edit-plan.json` 的 `planned_operations` 会列出 Lightroom 和 Photoshop 的完整操作链，`color_plan`/`detail_plan` 记录色彩、锐化和降噪参数，`plan_consistency` 校验摘要与可执行图一致。执行后 `execution_audit` 会标记每个操作的真实状态，并记录 Lightroom 恢复和被跳过的设置。批量准备阶段另有 `preparation-progress.jsonl`，聊天生图回写后会生成 `*.chatgen-resume.json`。

当 Lightroom/Photoshop 正在运行时，可直接从最近检查点继续；适配器未配置环境变量也会自动使用本机适配器：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/execution_engine.py" \
  --plan "/绝对路径/新的运行文件夹/execution-plan.json"
```

适配器必须返回结构化 JSON，并提供操作 ID、输出路径、哈希和必要的图层/蒙版/导出证据；缺失证据的结果保持失败或等待态。断点恢复完成后，可只同步顶层报告而不重复执行：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/execution_engine.py" \
  --plan "/绝对路径/新的运行文件夹/execution-plan.json" \
  --sync-report
```

质量门会根据真实渲染像素重新评分。如果原片过暗、主体信息不足或提升未达到阈值，报告可能显示“已完成执行但不建议发布”；这是质量拒绝，不是运行失败。此时仍保留 PSD/JPG、前后证据和质量报告，便于重新调整导演目标或候选参数。

审核时直接回复联系表编号，例如：

```bash
python3 "<PHOTO_SKILL_ROOT>/scripts/apply_review_decisions.py" \
  --report "/绝对路径/新的运行文件夹/report.json" \
  --default-lane A \
  --decision "8、11 淘汰，其余保留"
```

这一步只把用户明确保留的照片放入待执行队列，之后由宿主按 Lightroom MCP、Photoshop 能力和当前聊天窗口内置 `image_gen` 的可用状态执行。没有内置工具时，相关操作会标记为待处理或降级，不会生成虚假的成功结果。

## 优秀作品与个人风格学习

对拥有合法使用权的参考作品，提供本地图片、来源链接、作者和许可证信息。技能只保存来源和高层次风格属性，不下载或复制互联网作品：

```python
from reference_style import register_reference, derive_style_recipe
register_reference(db_path, local_path, "样片名称", source_url, "CC0", category="landscape-nature")
derive_style_recipe(db_path, category="landscape-nature")
```

连续多次反馈后，风格记忆才会升级为可执行的 Lightroom/Photoshop guidance recipe；单次“太暗”不会改变全部照片。
